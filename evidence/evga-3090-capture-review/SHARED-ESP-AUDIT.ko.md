# 공유 ESP GPU 미사용 부팅 인계 시험

[English](SHARED-ESP-AUDIT.en.md) | [한국어](SHARED-ESP-AUDIT.ko.md)

이 새로운 시험 EFI는 Windows 전용 공유 ESP 설계를 위한 빌드 전용 후보입니다. 로드된 자체 장치가 고정된 Windows ESP GPT 장치 경로를 가진 유일한 파일 시스템 핸들인지 확인하고 USB 경로 또는 중복 일치를 거부합니다. 그 후 같은 장치의 기존 `\EFI\Microsoft\Boot\bootmgfw.efi`를 로드하고 로드된 이미지 장치를 검사한 뒤 시작합니다. GPU 드라이버 열거/해제, GPU 레지스터 접근, PCI 설정 변경, 잠금 해제, 파일 또는 펌웨어 변수 쓰기, 부팅 순서 변경은 수행하지 않습니다. 해당 실행은 Windows를 직접 시작하며 기존 Limine 항목을 변경하지 않습니다.

기여자는 이 EFI를 공유 ESP에 성공적으로 스테이징했다고 보고했습니다. 아직 **부팅 항목으로 등록하거나 실제 하드웨어에서 실행하지 않았습니다**. 아래의 스테이징 전용 스크립트가 준비됐지만 일회성 선택 및 복구 절차는 아직 검토되지 않았습니다. 동일 볼륨 검사는 USB에서 EFI를 부팅하면 거부하므로 USB 부팅만으로 이 시험을 수행할 수 없습니다. 펌웨어가 이미지 로드 또는 Windows 인계 중 거부하거나 멈출 수 있으며 펌웨어 부팅 선택 또는 전원 종료가 필요할 수 있고 복구는 입증되지 않았습니다. **선택 및 복구 경로를 검토하기 전에는 파일을 부팅하거나 등록하지 마세요.**

정확한 Windows ESP GUID로 로컬 빌드합니다. 컴파일러 경로는 다를 수 있습니다.

```powershell
./research/profile/build-shared-esp-audit.ps1 -WindowsEspGuid "c36c3e86-02aa-4f76-af1b-96e327f9d1c1"
./research/profile/test-shared-esp-audit.ps1
```

로컬 빌드 경로는 `internal-boot/boot/build/shared-esp-audit/AUDIT.EFI`, 크기 4,608바이트, SHA-256 `5490224b49b8a4680f82a453020da47cbfa19775f2c835e15ba1fa98b60fec5d`입니다. 다른 도구체인은 해시가 다를 수 있습니다. PE 검증을 통과했습니다. 모의 UEFI 서비스로 올바른/다른/중복/USB/누락 파티션 핸들, 올바른 Windows 경로와 인계, 잘못된 로드 이미지 장치, 로드 실패 및 중복 거부를 검사했습니다. 이는 호스트 시험이며 실제 UEFI 동작 또는 성공적인 잠금 해제의 근거가 아닙니다.

## 선택적 스테이징 전용 시험

스크립트는 로컬 빌드 소스/매니페스트와 정확한 시스템 파티션 GUID를 검증하고 FAT32 볼륨을 요구하며 상위 경로의 재분석 지점을 검사합니다. 이전에 보고된 Windows 및 Limine EFI 해시를 비교한 뒤 새 `EFI/EVGA-SHARED-AUDIT.EFI` 파일을 기존 파일을 대체하지 않는 방식으로 생성하고 새 파일과 두 부팅 파일의 해시를 확인합니다. 기존 파일 덮어쓰기, 부팅 항목 생성, 부팅 순서 변경 및 재부팅을 의도적으로 수행하지 않습니다. `-WhatIf`는 복사를 건너뛰며 복사 작업 내부의 부팅 파일 해시와 대상 검사는 실행하지 않습니다. 부분 복사 또는 복사 후 검증 실패 시 자동 삭제하지 않으므로 파일을 보존하고 오류를 보고하세요.

**위험:** 사용 중인 Windows/CachyOS 공유 ESP에 새 파일을 씁니다. 파일 시스템 오류, 중단 또는 예상하지 못한 외부 변경으로 부팅이나 데이터에 영향이 있을 수 있으며 보존과 복구는 보장되지 않습니다. 백업을 준비하고 기기 소유자가 위험을 수용하는 경우에만 진행하세요. 검사는 검사와 사용 사이의 경쟁 상태나 펌웨어 동작을 증명하지 않습니다. 전체 스테이징 스크립트는 모의 저장소 및 부팅 파일 해시를 사용하는 시험 환경을 통과했으나 이후 기여자가 실제 ESP에서 두 부팅 파일의 해시 검사와 스테이징이 성공했다고 보고했습니다.

위의 빌드 후 관리자 PowerShell에서 먼저 계획을 확인하고 수용할 경우에만 스테이징합니다.

```powershell
./research/profile/stage-shared-esp-audit.ps1 -WindowsEspGuid "c36c3e86-02aa-4f76-af1b-96e327f9d1c1" -WhatIf
./research/profile/stage-shared-esp-audit.ps1 -WindowsEspGuid "c36c3e86-02aa-4f76-af1b-96e327f9d1c1"
```

출력이나 오류를 보내 주세요. 거부된 스테이징 후 파일을 삭제하거나 반복하지 마세요. 기존 Windows/Limine 해시는 관찰된 값을 고정하므로 정상적인 파일 업데이트도 스테이징을 거부하며 검토가 필요합니다.

## 기여자 스테이징 결과

2026-10-28 기여자는 4,096바이트 빌드의 SHA-256 `cfd24d9a1bdcf9fba0c1a7cd0bd314bf494d91c00bb39e3e30d2da87bcd4bbe5`, 호스트 모의 검사 10건 통과, 새 파일 스테이징 및 두 기존 부팅 파일의 해시 검사 성공을 보고했습니다. 이는 보고된 스크립트 출력이며 ESP를 독립적으로 검사하거나 부팅을 시험한 것은 아닙니다. 부팅 항목은 변경하지 않았습니다.

## USB 실행기 시험

별도의 USB 실행기는 고정된 ESP에서 스테이징된 감사 EFI를 로드하며 펌웨어 부팅 항목이나 순서를 변경하지 않습니다. 감사 EFI는 Windows로 직접 인계를 시도합니다. 이 시험은 같은 ESP에서의 로드를 확인하며 자동 잠금 해제를 제공하거나 GPU에 접근하지 않습니다. 실제 펌웨어 인계는 아직 입증되지 않았습니다. 실행기는 로드된 이미지의 장치를 확인하지만 실행 시 감사 파일의 해시를 계산하지 않습니다. 스테이징 스크립트는 복사 전후 Windows에서 보고된 감사 해시를 검사하나 이후 변경까지 막지는 못합니다.

`EFI` 디렉터리가 없는 별도의 FAT32 USB를 사용하세요. 스크립트는 기존 디렉터리를 거부하고 포맷하지 않습니다. USB 및 시스템/부팅 파티션 여부를 확인하지만 저장소 오류나 중단으로 데이터가 손실될 수 있으므로 USB를 백업하세요. 서명되지 않은 EFI가 거부되거나 펌웨어가 멈출 수 있습니다. Windows가 시작되지 않으면 전원을 끄고 USB를 제거한 뒤 일반 Limine 또는 Windows 부팅 항목을 선택하세요. 복구는 보장되지 않습니다. 펌웨어 설정을 영구 변경하지 않도록 설계되었지만 부팅 복구는 검증되지 않았습니다.

빌드와 호스트 시험 후 `stage-shared-esp-launcher.ps1 -Drive <letter> -WindowsEspGuid <guid>`로 지정된 USB에 준비합니다. `-WhatIf`는 복사를 생략합니다. 기존 EFI 또는 캡처 USB는 덮어쓰지 않습니다. 실패 시 부분 파일을 보존하세요. 현재 검증은 모의 시험이며 실제 부팅은 대기 중입니다.

## 기존 USB 재사용

선택 사항인 `-ReuseExisting`은 USB/FAT32와 고정된 감사 파일을 검사하고 `EFI/BOOT/BOOTX64.before-shared-audit.efi` 백업을 덮어쓰지 않고 생성한 뒤 원본 해시와 비교하고 USB 부팅 파일을 교체합니다. 준비 전에 원본 SHA-256을 기록하세요. 복원 스크립트는 기록된 해시와 현재 실행기 매니페스트를 요구하고 두 파일을 확인한 후 백업을 복원하고 검증하며 백업을 보관합니다. 캡처는 의도적으로 변경하지 않습니다. 먼저 USB를 별도 저장소에 백업하세요. 중단, 파일 시스템 오류 또는 부분 쓰기로 부팅이 불가능해질 수 있으며 복구는 보장되지 않습니다. 기존 백업이 현재 부팅 파일과 일치할 때만 재사용하며 불일치는 거부합니다. 오류 증거를 보존하세요. 이 작업은 기여자의 USB가 아닌 로컬 모의 시험에서 검증했습니다.

실행기는 이미지 로드와 장치 확인 후 `AUDIT LOADED FROM PINNED ESP`를 10초 동안 표시합니다. 이 메시지는 로드 지점을 보여 주지만 감사 EFI의 실행이나 Windows 인계 완료를 증명하지 않습니다. 펌웨어 Stall 지연은 실제 하드웨어에서 검증되지 않았습니다.
