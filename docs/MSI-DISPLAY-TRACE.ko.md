# MSI 화면 복귀 진단: 복구 전 기록 확보

영수증 잠금 해제는 EFI에서 완료했으나 DisplayPort 복귀에 수동 전원 차단이
필요했다. 기존 보고는 복구 부팅 상태이므로 실패 세션의 그래픽 드라이버 초기화를
보여주지 못한다. 다음 진단은 정상 Windows 제어 부팅 추적이며 EFI 재시도,
재무장 또는 GPU 리셋 변경을 허가하지 않는다.

## 방식

christian-boot-trace.ps1은 고유 WPR 부팅 자동 기록기와 SYSTEM 시작 작업1개를
구성한다. 사용자 프로필은 설치된 GPU.Light의 키워드를 사용한 DxgKrnl만 기록하며
스택/시스템 수집기 프로파일링은 없다. 주 순환 버퍼는32MiB이다. 시작30초 뒤
작업이 추적을 저장하고 자기 작업을 제거한다. 성공한 WPR stopboot는 자동 기록기
구성도 제거한다. 실패하면 자기 이름의 인스턴스만 취소하며 자동 재시도는 없다.

작업/의존 파일은 Administrators/SYSTEM 전용 ProgramData 폴더에 두고 등록 전
소유자/파일 ACL을 설정한다. 상태는 작업 파일/의존 해시와 정확한 작업 명령을
바인딩한다. 작업/파일 변경, 동일 부팅 호출, 기존 상태 및 이미 시작한 종료는
거부한다. 실제 Windows 부팅 UTC를 기록하므로 복구 부팅 추적을 이전 실패 부팅
추적으로 오인하지 않는다.

Microsoft WPR 부팅 기록 문서:
https://learn.microsoft.com/en-us/windows-hardware/test/wpt/wpr-command-line-options#boottrace
개발 호스트의 wpr 도움말/프로필 파서로 명령과 프로필을 확인했으나 Christian
컴퓨터의 실제 시작 동작 검증은 아니다.

## 사용자 제어 테스트

고정된 단일 스크립트를 관리자 권한으로 -AcceptTraceSetup과 실행한다. 임시 부팅
추적 레지스트리/시작 작업, 프로파일링/시작 오버헤드 및 로컬 진단 메타데이터를
허용하는 옵션이다. USB를 제거하고 Windows에서 수동 Restart만 한다. 스크립트는
재부팅하지 않는다. Windows 복귀90초 뒤 같은 스크립트 -Mode Collect를 관리자로
실행하고 christian-boot-trace 요약 ZIP 및 정상 화면 복귀 여부를 보낸다. ETL에는
프로세스/이미지 메타데이터가 있을 수 있어 원본은 로컬에 남기며 ZIP/자동 업로드에
포함하지 않는다.

추적이 완료되지 않았다면 같은 스크립트 -Mode Cancel을 관리자로 실행하고 보고를
수집한다. 소유 WPR 인스턴스와 변경되지 않은 소유 작업만 취소한다. 실패 상태를
보존하고 설정 재시도/마커 삭제/소비된 EFI 부팅을 하지 않는다. 정상 제어 부팅에서
Windows 자체가 실패하면 보고하며 복구 보장 또는 EFI 재시도를 추론하지 않는다.

## 검증과 남은 경계

WindowsPowerShell5.1에서 작업 성공/실패/거부8개, 반복 거부, 고립된 네이티브
인수, 보호 준비/작업 설정 및 WPR 설정 실패 정리를 OS 변경 모의로 검증했다.
설치된 WPR 파서가 실제 프로필(256KiB x128, DxgKrnl0x277, 시스템 수집기 없음)을
수락했다. 비관리자 실행은 설정 없이 오류 ZIP을 생성했다. 개발 세션은 관리자
권한이 아니므로 실제 작업 등록, 부팅 추적 구성 및 재부팅 후 자동 저장은 다음
제어 테스트에서 검증해야 한다. 로컬 재부팅 또는 추적 활성화는 없었다.
