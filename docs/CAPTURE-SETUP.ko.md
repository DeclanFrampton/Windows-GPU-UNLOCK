# 하나의 진단 흐름

[English](CAPTURE-SETUP.en.md) · **한국어** · [프로젝트](../README.ko.md)

소스 ZIP 전체를 압축 해제한 뒤 **`Start-Capture.cmd`**를 실행하세요.
결과 수집 후에도 같은 파일을 다시 실행합니다. 도구가 로컬 세션을 기억하고
하나의 `report.json`을 만듭니다.

Windows 정보 수집과 저장 파일 검토에는 메인보드나 GPU 모델 허용 목록이
없습니다. AMD/Intel, 모바일 GPU, 소프트웨어 어댑터, 같은 모델의 여러 GPU도
관찰 대상입니다. NVIDIA LOCAL 프로필 허용 여부는 보고서의 별도 평가입니다.

## 시작

1. `Start-Capture.cmd`, `tools`, `research`, `internal-boot`, `deps`를 함께
   유지한 상태로 소스 전체를 압축 해제합니다.
2. **`Start-Capture.cmd`**를 더블 클릭합니다.
3. 기존 캡처가 있으면 폴더를 입력하고, 없으면 Enter를 누릅니다.
4. 창에 표시된 **`report.json`**을 검토한 뒤 공유합니다.
   기본 위치는 `Documents\GPU-Unlock-Diagnostics`입니다.

캡처 폴더를 실행기에 끌어 놓아도 됩니다. 관련 `DIAGnn.TXT`, `IMGnn.BIN`,
`PROM.BIN`은 원래 폴더에 함께 보관합니다. 하위 폴더를 찾되 서로 다른
캡처의 이미지는 혼합하지 않습니다.

Windows 관찰에는 Python, 컴파일러, USB, 관리자 권한 또는 지원 GPU 모델이
필요하지 않습니다. Python은 저장된 캡처 파싱에만 필요합니다. 없어도
Windows 보고서와 의존성 설명을 만듭니다. 포함된 graph-only 템플릿 준비에는
LLVM/MSVC가 필요하지 않습니다.

Windows 정책이 PowerShell의 스크립트 시작 자체를 차단하면 보고서를 만들 수
없습니다. 정확한 오류를 보존하고 보고하세요. 실행 정책이나 인코딩 명령으로
우회하지 않습니다. 기존 파일은 관리자 또는 정책상 허용된 분석 환경에서
오프라인으로 검토할 수 있습니다.

## 자동 선택

| 입력 | 같은 실행기에서 수행하는 작업 |
|---|---|
| 현재 Windows | 제한된 하드웨어/드라이버 정보와 디스플레이 부모 관계 수집 |
| 알 수 없는 어댑터, 혼합·중복 GPU | 관찰한 어댑터를 유지하고 공유 부모를 불투명 노드 ID로 표현 |
| 기존 진단 로그 | 파일/해시 검증, 그래프 관찰, 기존 LOCAL 프로필 검사 |
| 이미지·EDID·wrapper/GOP 텍스트 | 해당 코드 식별, 자식 관계, 명령 경계 또는 GOP 관찰 검사 선택 |
| 불완전하거나 거부된 캡처 | 확보한 관찰과 이유를 유지하며 추가 EFI 부팅을 자동 요청하지 않음 |
| 변경 없는 이전 입력 | 바이트/소스 해시를 다시 확인한 뒤 결과 재사용 |
| 준비된 graph 세션 | 영수증·매체·소스 확인 후 기존 로그 수집, 재준비하지 않음 |

`CollectionHost`는 분석 PC이고 `SavedEvidence`는 저장된 증거입니다.
다른 사람의 파일을 분석한다고 두 시스템을 동일하게 간주하지 않습니다.
영수증 일치는 준비·매체·소스의 연결이며 캡처 출처나 현재 호스트의 증명이
아닙니다. 공개 보고서에서 입력 경로, 원시 인스턴스 ID, 파티션 GUID,
펌웨어 이미지, 임의 예외 메시지는 제외합니다. 게시 전에 검토하고
`session.json`, 로컬 영수증과 원본 캡처는 비공개로 보관하세요.

## 선택 사항: graph-only EFI 한 번

실제로 확인된 x64 UEFI Windows, 관리자 프로세스, Secure Boot 비활성,
완전히 복호화된 시스템 볼륨, 하나로 식별된 내부 Windows ESP,
읽을 수 있는 디스플레이 목록, 일치하는 소스/템플릿 및 사용자가 선택한
쓰기 가능한 비시스템 FAT32 USB가 필요합니다.

메인보드 이름, BIOS/CPU 모델, GPU 제조사나 이슈 번호로 별도 구현을
선택하지 않습니다. 현재 소스·인벤토리·Windows 복귀 대상·USB를 해당 준비에
연결합니다. USB 문자·이름·모델·용량을 확인한 뒤 `PREPARE`를 입력하세요.
기존 이동식 부트 로더를 보존하고 검증합니다. 포맷, 부팅 항목 등록,
자동 재시작은 하지 않습니다.

graph 이미지는 펌웨어 핸들/프로토콜 관계, PCI 헤더, 확보 가능한 GOP를
관찰합니다. GPU MMIO, PROM/이미지 덤프, 드라이버 해제, unlock은 하지
않습니다. 없는 GOP 정보를 메인보드 가정으로 채우지 않습니다.

준비 후 완전히 종료하고 펌웨어 메뉴에서 USB를 **한 번만** 선택합니다.
테스트 키 입력은 필요하지 않습니다. 지정된 Windows 부트 로더로 복귀를
시도합니다. 2분 안에 Windows가 시작되지 않으면 전원을 끄고 USB를 제거한
뒤 정상 Windows Boot Manager를 사용합니다. 수동 복구 여부를 기록하세요.
복구는 보장되지 않으며 **시도한 진단을 반복하지 마세요.**

Windows 복귀 후 원래 USB를 연결하고 **`Start-Capture.cmd`**를 다시
실행합니다. 기존 캡처를 수집·검토합니다. 문자 변경은 기록된 디스크/파티션
식별로 찾을 수 있습니다. 다른 USB, 변경된 EFI/소스, 불완전한 준비는 자동
재준비로 이어지지 않습니다.

ARM, 32비트, 레거시 PC는 Windows/저장 파일 검토 경로를 유지합니다.
포함된 EFI는 x64용입니다. 정책·암호화 상태가 불명확하면 해당 EFI 동작만
사용할 수 없는 이유를 보고합니다.

## 재개와 결과

같은 실행기로 기본 세션을 재개합니다. 여러 스크립트, 이슈 번호, 캡처 수를
기억할 필요가 없습니다. Python 경로, 별도 세션, Windows 조회 없는 오프라인
명령은 [영문 안내](CAPTURE-SETUP.en.md#resume-and-dependencies)를 참고하세요.

`report.json`에는 관찰, 평가, 출처 해시, EFI 사용 가능 여부와 다음 동작
하나가 있습니다. LOCAL 검사의 `candidate`는 unlock 허가가 아닙니다.
`hardware_tested`와 `write_eligible`은 false입니다.
프로필 생성, 심층 probe, 펌웨어 자산 준비나 unlock을 자동 호출하지 않습니다.

PowerShell·Python·C 호스트/모의 검증은 입력 변경, 혼합·중복 어댑터,
중단된 준비, 매체 변경, 부분 로그 등을 검사합니다. 추가 실제 시스템의
EFI 부팅·Windows 복구·GPU unlock이 검증되었다는 뜻은 아닙니다.
