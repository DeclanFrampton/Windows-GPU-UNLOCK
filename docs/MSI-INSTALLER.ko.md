# MSI 재사용 설치기 준비

정확한 참석 USB 잠금 해제 및 동일 부팅 텐서 성능 향상은 입증되었다. 새 페이로드
패키지와 로컬 설치 상태 준비는 로컬 검증만 완료했으며 재사용 설치의 하드웨어
자격은 아니다. 영구/무인/공유 ESP 또는 자동 재무장을 활성화하지 않는다.

## 로컬 빌드와 준비

일치하는 소스 체크아웃에서 다음을 실행한다.

```powershell
& .\research\profile\build-msi-profile.ps1 -OutputDirectory C:\GPU-Unlock\Packages\MSI-01
& .\research\profile\test-msi-package.ps1 -PackageDirectory C:\GPU-Unlock\Packages\MSI-01
& .\research\profile\prepare-msi-install.ps1 -PackageDirectory C:\GPU-Unlock\Packages\MSI-01
```

기존 정확한 MSI 쓰기 어댑터와 Windows ESP 핀으로 EFI/프로필/소스/PE/라이선스
목록과 ZIP을 생성한다. 로컬 준비기는 파일 크기/해시, 프로필과 빌드 정책을
검증한 뒤 새 C:\GPU-Unlock\MSI-Profile에 복사한다. installation-plan.json은
PreparedNotInstalled 상태이다. NVIDIA 자산은 포함하지 않는다. arm 마커,
USB/ESP 쓰기, 펌웨어 변수, 부팅 항목, 예약 작업 또는 재시작은 없다. 기존 상태는
보존하고 거부하므로 우회를 위해 삭제하지 않는다. 새 준비에는 새 폴더를 사용한다.

## 다음 참석 재무장 구현

현재 EFI는 고정 MSI-UNLOCK.ARMED를 소비하며 메모리 spent 플래그는 한 번의 호출에만
유효하다. 검증한 단발성 전달에는 적합하지만 영속적 재사용 시도 식별자가 아니다.
설치기가 고정 마커를 재생성하거나 MSI-UNLOCK.STAGED를 지우게 하지 않는다.

1. 각 빌드/실행에 고유 ID 및 변경 불가 패키지/이미지/자산 해시를 부여한다.
2. 수명주기/MMIO 전 STARTED 영수증을 영속 기록/flush하고 정확한 arm을 소비한 뒤
   읽어 확인한다. 누락/불일치/미완료/실패 영수증은 다음 실행을 금지한다.
3. 트랜잭션 격리, 대상 검증, 디코드 해제, 소유권 및 자산 해제 성공 뒤에만 별도
   FINISHED 영수증을 쓴다.
4. Windows 제어기는 정확한 이전 패키지/영수증과 사용자 Windows 복귀 보고를 확인하고
   원본과 소유 파일 백업을 보존한다. 새 참석 동의는 새 ID이며 이전 허가 재생성이 아니다.
5. 설치/취소/수집/복원, 쓰기 중단 및 모든 미완료/실패 거부를 로컬 검증한 뒤
   새로운 위험을 안내한 참석 하드웨어 재무장 1회를 검증한다.

## 무인 부팅과 지속성

무인 잠금 해제는 선택한 부팅에서 가드 트랜잭션을 실행하는 것이며 하드웨어 변경의
영구성을 뜻하지 않는다. arm 재생성 또는 조용한 재시도 작업을 추가하지 않는다.
참석 재사용 경로를 먼저 검증하고 시도 제한, 영속 실패 잠금, 정상 Windows 인계,
명시적 비활성화/복원을 가진 제한적 선택 정책을 검토한다. 내부 ESP는 식별,
원본 장치, 로그/자산과 복원 검증이 별도로 필요하다. EVGA 프로필로 대체할 수 없다.

정상 재시작 후 성능 비교는 대기 중이며 완전 전원 차단 후 지속성은 미입증이다.
동일 부팅 결과로 이를 단정하거나 영구 펌웨어 변경을 시도하지 않는다. 테스트한
구성처럼 Secure Boot는 비활성 상태이며 서명/신뢰 부팅은 별도 설계이다.

## 로컬 검증

실제 91,648바이트 MSI EFI 빌드/PE 검증(AMD64 EFI, imports0, NX/ASLR)을 완료했다.
Windows PowerShell5.1에서 목록/로컬 상태 생성, 기존/중첩 상태 거부, 변경/누락 파일,
중복 목록 및 자동 정책 거부를 확인했다. 하드웨어 실행은 없었다. 이는 정확성
검사이며 진위 서명이나 실제 설치 증거가 아니다.

## 준비된 시도 식별자

로컬 준비는 임의의 변경 불가 시도 ID, 패키지/EFI/자산 목록 해시 및 검토한
DIAG14 증거 해시를 가진 Attempts/attempt-0001.json도 기록한다. CreateNew,
배타적 접근과 영속 Flush(true) 뒤 식별자/바인딩을 읽어 확인한다. 상태는
PreparedNotArmed이며 실행 허가가 아니다. 기존 시도 항목이 있으면 미완료,
실패 또는 불명확 상태를 포함해 다른 계획을 거부한다. 기존 기록은 덮어쓰지 않는다.
이는 호스트 준비 기반이며 EFI STARTED/FINISHED 영수증 생성과 성공 결과에 따른
attempt2 생성은 아직 구현해야 한다. 현재 도구는 계획을 arm 마커로 바꾸지 않는다.

바인딩, 미완료 계획 거부와 덮어쓰기 시도 후 원본 해시 보존도 테스트했다.
사용자용 단일 준비 스크립트는 이전 준비 리비전에 고정되어 있다. 새 저널을 위해
기존 사용자 상태를 조용히 업그레이드하거나 교체하지 않는다.

## 정확한 시도별 EFI 영수증 구현

build-probe.ps1의 영수증 변형은 32자리 16진수 MsiAttemptId를 받아 각각 다른
MA<ID>.ARMED/STARTED/FINISHED 경로를 포함한다. ARM ID를 정확히 확인하고 기존
STARTED/FINISHED를 거부하며 드라이버 해제 전에 STARTED를 쓰기/flush/닫기/읽기
확인한 뒤 arm을 소비한다. 쓰기/flush/읽기 확인/닫기/arm 삭제 실패 시 대기하며
부분 STARTED도 반복을 차단한다. FINISHED는 트랜잭션, 자원 정리 및 진단 기록
성공 후 Windows 인계 전에 기록/확인한다. FINISHED 자체는 Windows 시작 증거가 아니다.

MsiAttemptId가 없으면 기존 단발성 빌드는 별도로 유지된다. 생성 구성은 private/
ignored이며 해시는 빌드 목록에 기록한다. 일반 캡처 오브젝트에는 시도/쓰기 플래그를
주지 않는다. Christian의 기존 상태 보고1566601541337481226은 이전 준비가 완성되었고
설치/재무장되지 않았으며 호스트 시도 계획은 없음을 확인했다. 조용히 이전하지 않고 보존한다.

93,696바이트 영수증 EFI 빌드/PE 검증을 통과했다. CPU 테스트는 트랜잭션 래퍼/반복
23개, 그래프17개, 영수증 시작13개 및 종료 실패6개를 통과했다. 미완료/완료 거부,
arm 불일치, 짧은 쓰기, flush/읽기 확인/닫기/삭제 실패를 포함한다. 하드웨어 실행은
없었다. 다음 실제 경계는 별도 식별자를 가진 참석 재무장 1회이며 자동 재시도,
무제한 재무장 또는 무인 배포는 구현하지 않았다.

미입증이다. 다음 하드웨어 시도 전 FLR 후 화면 인계의 관리자 검토에서 근거 있는
변경 또는 추가 진단 능력이 필요하다. 일반 수집기 추가나 변경 없는 EFI 반복은
빠진 원인 진단을 대신하지 않는다.
